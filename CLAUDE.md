# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

LaprdusTTS is a Croatian/Serbian/Bosnian/Slovenian text-to-speech (TTS) engine supporting:
- **SAPI5** (Windows Speech API) for system-wide TTS integration
- **NVDA** screen reader synthesizer driver

It has two kinds of voices:
- **Concatenative** voices (Josip, Vlado and the voices derived from them) are rendered from pre-recorded phoneme WAV files by TD-PSOLA. See "Recorded Voices" below and `docs/concatenative.md`.
- **Formant** voices (Zvonko, Stojan, Mirsad) are synthesized entirely by rule and need no data files. See "Formant Voices" below.

### Processing Pipeline

1. Text → `TTSEngine::preprocess_text()` → Number expansion, dictionaries
2. → `InflectionProcessor::analyze_text()` → Segment into clauses by punctuation and at line breaks (a line break ends the clause with the newline pause, so the next line starts a sentence: a capital S or K there is the preposition; a colon or exclamation mark glued to the next character, as in `12:30`, is not a clause end: it stays in the text and is read by name by the front end's `SYMBOLS` table; a glued period stays only before a file extension or domain label of up to five letters or digits in one case, `datoteka.txt`, `www.index.hr`, and after a single letter, where it is an abbreviation dot, silent, with the letters read by name: `s.a.r.s.`, `U.S.A.`; every other glued period ends the clause, `Preslušano.Nestajuća`; the decimal point is written by the number converter as U+2024 so it survives, `3.14` tri točka četrnaest; the number converter reads every digit group after a period as a whole number (`1.317` jedan točka tristo sedamnaest), the decimal comma as *zarez* (but a comma between the single digits of a phone number spelled out by a screen reader, `+ 1 2 3,5 6,7 8 9,8 7 6`, as a comma pause), clock times `12:30` and dates `7.10.2026` / `7. 10. 2026.` without the separators, a number of up to four digits with a period before a lowercase word as the cardinal with the period silent: `7. listopada` sedam listopada, `1990. godine` (no ordinals: they would need the noun's case), and sets a number glued to letters off from them (`u20:03` u dvadeset nula tri, `5kg`), silencing the period that joins a word to those letters: `7.listopada.u20:03` sedam listopada u dvadeset nula tri; the front end expands no abbreviation, spells a vowelless one (`dr.` de er), and silences the colon of `https://`)
3. → `formant::Frontend::process()` → phones with stress, words, clause kind (both kinds of voices); for Slovenian `Frontend::process_slovenian()` with the rules and lexicon of `formant_slovenian.cpp`
4. → Recorded voices: `concat::plan_clause()` (durations, pitch contour) → `concat::render()` (TD-PSOLA)
   Formant voices: `ClauseBuilder` → `KlattSynth`
5. → Output 16-bit PCM @ 22050Hz mono; rate, pitch, volume and intonation are applied at the source by both

### Phoneme System

- **Format**: 16-bit PCM WAV, 22050 Hz, mono
- **Storage**: Packed `.bin` files (Josip.bin, Vlado.bin) or raw WAV directory
- **Croatian phonemes**: A-Z + č, ć, đ, š, ž, lj, nj, dž (the Slovenian open e/o, close e/o, schwa and [w] of the formant voices are rendered by the recorded e, o, e and u)
- **Analysis at load**: DC removal, pitch marks, voicing, burst onset per recording (`unit_bank.cpp`)
- **Joins**: pitch-synchronous crossfade of whole periods (no fixed crossfade, no truncation)

**Every voice speaks every language.** Language (hr, sr, bs, sl) is chosen separately from the voice, as in eSpeak or Eloquence; a voice's `language` / `language_code` in the registry is only its *native* language, spoken until the host asks for another. The language selects the text front end (letter-to-sound rules, accent lexicon, letter names when spelling) and the number words (tisuća/milijun hr, hiljada/milion/dvesta sr, hiljada/milion/dvjesto bs, tisoč/milijon/dvesto sl) for every voice, Josip and Vlado included. No voice has Slovenian as its native language: every voice speaks it when asked. C API: `laprdus_set_language(h, tag)` ("hr", "hr-HR", "hr_HR", "hrv", "sr-Latn-RS", "srp", "bs", "bos", "sl", "sl-SI", "slv", "Croatian", "hrvatski", "Slovenian", "slovenščina", any case; NULL/"" = back to the voice's native language), `laprdus_get_language(h)` ("hr-HR" | "sr-RS" | "bs-BA" | "sl-SI"), `laprdus_get_language_count()` (4), `laprdus_get_language_info(index, &LaprdusLanguageInfo)` (code, short_code, lcid 0x041A/0x081A/0x141A/0x0424, english_name, native_name Hrvatski/Srpski/Bosanski/Slovenščina). Once set, the language sticks across later `laprdus_set_voice()` calls. C++: `TTSEngine::set_language(VoiceLanguage)` works for every voice and sets the number dialect, `TTSEngine::language()` reads it, `initialize()` / `initialize_formant()` start in the voice's native language (call `set_language()` after them when the host chose one), `laprdus::parse_voice_language()` and `voice_language_code/short_code/lcid/english_name/native_name()` live in `types.hpp`. Per platform: NVDA "Language" combo (hr/sr/bs/sl, default from NVDA's UI language; `LangChangeCommand` switches among the four and ignores other languages); SAPI5 four tokens "Laprdus Croatian" / "Laprdus Serbian" / "Laprdus Bosnian" / "Laprdus Slovenian" that set the language and speak with the voice from `settings.json` (`voice.default`, empty = zvonko; no language key); Android 72 system voices `<id>-<lang>` (the requested locale sets the language, the configured voice is kept; a request without a locale and the in-app Speak button get the system language when Laprdus speaks it, else the Language setting (`Language.effective()`); "Force language" = speak the Language setting everywhere, whatever the system and the apps ask for; with it off and a supported system language the Language dropdown is shown disabled with the system language); Apple one `AVSpeechSynthesisProviderVoice` per voice × language, identifier `com.hrvojekatic.laprdus.<id>.<lang short>`, a Language picker in the app; CLI `-L hr|sr|bs|sl` (without it a voice speaks its native language; `-l` lists voices with their native language); Speech Dispatcher LIST VOICES returns every voice for every language, SET LANGUAGE calls `laprdus_set_language()` and keeps the voice (`spd-say -l sr -y "Zvonko"`), MALE1 = zvonko, MALE2 josip, MALE3 djedo, FEMALE1 baba, CHILD_MALE detence for all four languages.

**Default voice: Zvonko everywhere**, for every language and platform (`laprdus_get_default_voice()` / `VoiceRegistry::default_voice_id()` = "zvonko": CLI `-v` default, Speech Dispatcher `MALE1`, Android `DEFAULT_VOICE` / fallback voice, NVDA, Apple, the Windows config GUI, SAPI5 `voice.default` empty). A voice the user has chosen is never replaced. The recorded voices stay available.

**Ids and names.** Ids are plain ASCII without diacritics on purpose (dj for đ, c for č/ć, s for š, z for ž): registration safety. Display names come from the registry (`LaprdusVoiceInfo.display_name`, UTF-8, no "Laprdus" prefix, no language suffix); platform UIs must not hard-code them (they may append a localized description: child, grandma, formant, singing). Old ids resolve to the renamed voice in `VoiceRegistry::find_by_id()`, `laprdus_set_voice()` and `laprdus_get_voice_info_by_id()` (djed → djedo, dijete → detence, baka → baba, klapa → dalmacija_klapa, pjevac → lika_velebit, pevac → solunac, solist → sarajevo_bembasa); `laprdus_get_current_voice()` returns the canonical id; UIs normalize a saved id before comparing it with the list. The spellings "Djed", "Djedo", "Baka", "Dijete", "Detenče", "Zvonko Orguljaš", "Klapa Zvonko", "Stojan Trubač", "Mirsad Solist" etc. must not appear anywhere: Detence, Baba, Đedo, and the preset names of the table.

`laprdus_set_voice()` applies the voice's base pitch itself (times the last `laprdus_set_pitch()` value), so derived voices sound right without a pitch call after every voice change.

`VoiceDefinition::synthesis` (`VoiceSynthesis::Concatenative` / `Formant`) tells the two kinds apart. Formant voices have no `data_filename`; `laprdus_set_voice()` accepts any data directory for them. A singing preset has a `base_voice_id` and no `data_filename` (or index >= 8). New voices must be appended to the registry: existing code and saved settings rely on the order of the first five.

### Audio Parameters (types.hpp)

```cpp
struct VoiceParams {
    float speed = 1.0f;       // 0.5 - 2.0 (tempo, time-stretching); formant voices 0.25 - 4.0
    float pitch = 1.0f;       // 0.25 - 4.0 (voice character pitch)
    float user_pitch = 1.0f;  // 0.5 - 2.0 (user pitch preference); formant voices 0.25 - 4.0
    float volume = 1.0f;      // 0.0 - 1.0
    bool volume_boost = false; // much louder speech: +14 dB, peak limiter and soft clipper, before the volume (every voice)
    float inflection_level = 0.5f;  // 0 monotone, 0.5 as measured, 1 twice the movements (every voice)
    float acceleration = 1.0f;      // rate multiplier 0.5 - 3.0 (every voice; VoiceParams::effective_speed())
    SpellingMode spelling_mode = SpellingMode::LetterSounds; // spelled letters: sounds ([b], [ts]; the default) or names (be, ce)
    int spelling_speed = 50;        // spelling cadence: lower values add silence; speech rate stays unchanged
};
```

## Formant Voices

Zvonko (hr), Stojan (sr) and Mirsad (bs) live in `src/formant/` and share the text preprocessing of the concatenative voices (emoji and pronunciation dictionaries, number expansion, clause segmentation). From there `TTSEngine::synthesize_segments()` hands each clause to `FormantSynthesizer::synthesize_clause()`:

1. `Frontend::process()` - Cyrillic → Latin, digraphs (lj, nj, dž), the ijekavian *ije* diphthong, syllabic r, spelled-out abbreviations; stress from accent marks in the text, the lexicon, suffix rules, or the first syllable; proclitics/enclitics; voicing and place assimilation.
2. `ClauseBuilder` - segment durations, formant targets and locus-based transitions, source amplitudes, and the F0 contour (word accents, declination, boundary movement chosen by the clause's punctuation).
3. `KlattSynth::render()` - glottal source, cascade formants for voiced sound and aspiration, parallel resonators for frication and bursts.

Things to know before changing them:

- **Speed, pitch and volume are applied at the source** (durations, F0, gain), so `VoiceParams::pitch` and `user_pitch` both simply scale F0.
- **Wider ranges; inflection level and acceleration are for every voice.** `VoiceParams::clamp()` allows speed and `user_pitch` from 0.25 to 4.0; the concatenative `AudioSynthesizer` narrows them to its 0.5-4.0 / 0.5-2.0 itself, so every platform may pass the wide range and let the engine sort it out. `inflection_level` (0-1, default 0.5) scales the whole F0 contour in semitones (0 is a monotone, 1 doubles every movement) and `acceleration` (0.5-3.0, default 1.0) multiplies the speed (`VoiceParams::effective_speed()`, capped at 8.0; the concat planner narrows the product to 0.5-4.0), so a host's rate slider reaches a higher or lower top rate. Both apply to the recorded voices too (`concat_prosody.cpp`), are `laprdus_set_inflection_level()` / `laprdus_set_acceleration()` in the C API, `speech.inflection_level` / `speech.acceleration` in `settings.json`, keys `inflection_level` / `acceleration` on Android and Apple, and every settings screen shows them with the voice settings, for every voice. `laprdus_get_nominal_wpm(voice)` (175 words/min for Zvonko at speed 1.0, times the voice's tempo) lets a UI print the top rate in words per minute: nominal × 2.0 (the host slider's top) × the Laprdus rate (the rate alone when forced) × acceleration, capped at 8.0 (recorded voices 4.0). The Speech Dispatcher module maps SSIP `pitch_range` onto the inflection level. The NVDA add-on uses NVDA's own controls instead: NVDA's Inflection slider sets the inflection level (0-100 → 0-1, inflection always enabled; `speech.inflection` and `speech.inflection_level` are not read), and Rate Boost multiplies every rate slider position by 3 through the acceleration (`speech.acceleration` is not read), as eSpeak's and OneCore's boost does.
- **settings.json of version 1.0** (no `inflection_level` key) is migrated when read (`parse_settings_json()` in `user_config.cpp`, mirrored in the NVDA driver): its `inflection` switch is ignored (it controlled 1.0's pitch jump at the punctuation, not the melody, so the level starts at the default 0.5), and an unforced `speed` / `pitch`, which 1.0 ignored, reads as 1.0 so the upgrade does not change the host's rate. Pause values mean the same in both versions; a colon pauses for the comma pause.
- **A host's rate and pitch scale the user's own.** The rate and pitch in Laprdus's settings are the voice's normal; TalkBack, VoiceOver, NVDA, SAPI5 and Speech Dispatcher ask relative to their normal (Android `speechRate` 100, SSML 1.0, SAPI rate 0, NVDA 50, SSIP 0), so every platform sets `laprdus_set_speed(setting × host)` and `laprdus_set_user_pitch(setting × host)`, clamped to the voice's range (`VoiceInfo.requestValue()` on Android, `VoiceCatalog.requestValue()` on Apple). The force switches (`force.speed` / `force.pitch`, `force_speed` / `force_pitch`) mean "ignore the host": the setting alone. Volume is not scaled (host volume, or 1.0 on Android, unless forced; on Apple the host's volume is VoiceOver's `<prosody volume="...dB">` of the request, read by `SSMLParser` per part, which used to be ignored). **Volume boost** (`VoiceParams::volume_boost`, `laprdus_set_volume_boost()` / `laprdus_get_volume_boost()`, `speech.volume_boost` in `settings.json`, key `volume_boost` on Android and Apple, CLI `-B`, a checkbox under the volume in every settings screen, off by default, every voice): a loudness maximizer after Google TTS's "amplify speech volume": both renderers drive the clause through `src/audio/volume_boost.hpp` before the volume is applied, a gain of `VOLUME_BOOST_GAIN` (5.0, +14 dB), a fast lookahead peak limiter with its ceiling above full scale (1.4) and a tanh soft clipper from 0.6 up, so a phone's earpiece in traffic gets a much louder signal that never clips hard and a host's volume control still works; Zvonko's median level rises by 11 dB and his loud stretches by 8 dB, Josip's by 5 and 4 dB, at the price of a mild saturation of the strongest vowel peaks (a limiter alone stalled at -8 dBFS and was not noticeable). See "Volume boost" in `docs/dev.md`. Speech Dispatcher has no force switches and reads the setting back with `laprdus_get_speed()` / `laprdus_get_user_pitch()` after `laprdus_load_user_config()`. Before this, an unforced Laprdus rate was ignored by every host, so the rate slider seemed dead next to the acceleration slider.
- **Android: the app and the TTS service have separate native engines** in one process: `LaprdusTTS.service` and `LaprdusTTS.app` (Hilt provides the latter). The JNI bridge keeps one `NativeEngine` per object and every native call takes its handle; there is no global engine. The service follows the app through saved state only: a newly saved default voice is loaded at once, and the user dictionaries switch or any dictionary write (`DictionaryRepository.changes`) reloads the dictionaries (`LaprdusTTS.reloadDictionaries()`: bundled, then the user's from `userDictionaryDir`). Sequences such as "set the request's rate and pitch, then synthesize" and voice loads run inside `LaprdusTTS.exclusive { }`.
- **Number words follow the language**, for every voice: `CroatianNumbers::set_dialect()` is set by `TTSEngine::set_language()` (tisuća/milijun/dvjesto for hr, hiljada/milion/dvesta for sr, hiljada/milion/dvjesto for bs, the Slovenian system for sl), starting from the voice's native language in `initialize()` / `initialize_formant()`; Josip speaking Serbian says *hiljada*, Stojan speaking Croatian *tisuća*. One and two agree with the feminine scale words in every dialect (dvije tisuće, dve hiljade, dvadeset jedna tisuća, dvije milijarde). Slovenian (Slovenski pravopis 2001 § 11, § 536, § 253): nič, ena, dve, tri, štiri; enaindvajset as one word; the invariable tisoč (dva tisoč, tristo en tisoč); en milijon, dva milijona, trije milijoni, štirje milijoni, pet milijonov, enaindvajset milijonov; ena milijarda, dve milijardi, tri milijarde, pet milijard; the decimal comma as cela (tri cele štirinajst, ena cela pet, nič celih pet), a period between groups of three digits as the thousands separator (132.457 sto dvaintrideset tisoč štiristo sedeminpetdeset; 3.14 stays tri pika štirinajst), a numeric date in the genitive (7. 10. 2026 sedmega desetega dva tisoč šestindvajset, 7. oktobra sedmega oktobra).
- **Slovenian** (`src/formant/formant_slovenian.cpp`, `Frontend::process_slovenian()`; "4a. Slovenian" in `docs/formant.md`): the shared tokenizer and clause structure with rules and a lexicon of its own. Eight vowels: the phones `EH` [ɛ], `OH` [ɔ] (every unstressed and short stressed e, o), `EE` [eː], `OO` [oː] (long stressed close é, ó), `AX` (the schwa written e: veter, pes, misel, the fleeting -er/-el/-en/-ek/-ec), and `W` for the l and v that are [w] (bil, delal, stol, nov, avto; word-initial v before an obstruent is the vowel u: vsak [usak]); lj/nj are l+j, n+j before a vowel and plain l, n otherwise; syllabic r is [ər]; final devoicing (grad [grat], but a preposition keeps its voicing before its host: od orača), regressive voicing assimilation, s/z before š/ž/č, n before k/g/h. Stress is dynamic (long or short, no tones: every word has `Accent::Neutral`): marks in the text (acute = long close, circumflex = long open, grave = short), then the lexicon, then rules (the always-stressed suffixes -írati, -ováti, -éti, -íšče, -ílo, -ízem, -álen, -ljív ...; the syllable before -ica, -ščina, -niti, -cija; otherwise the second-last syllable). The lexicon: the generated `formant_slovenian.inc` (93,000 forms and 69,000 stems covering the word forms of 101,000 Sloleks 3.1 lemmas: every hand-accented one and the automatic ones of frequency 100 or more; front-coded in blocks of 16 and binary-searched in place: no start-up cost, about 1.3 MB of source and 0.9 MB in the library) plus `HAND_ENTRIES` in the .cpp, which win and hold only words Sloleks lacks and dictionary-backed deviations (about 60 entries since 2026-10-30). The generator reads a homograph by the corpus frequency of the form, not of the lemma (veselím, not the adjective's vesélim), counts a proper name a tenth (sobóta, not Múrska Sóbota), makes a fleeting e a schwa (rékel rêkla, začétek začétka, not vídel vídela or a verb's -em), applies `CORRECTIONS` (lemma-level fixes from SSKJ²/SP: dánəs, səznàm, the first-syllable teens) and then simulates the C++ lookup, hand entries included, over every form, listing whole any form a stem misreads (postavít*, the stem of postavítev, had read postaviti as postavíti). Measured on the tagged corpus SUK 1.1 with Sloleks as the reference (`docs/formant.md`, 4a): 99.4 % of the stressed syllables of 297,000 content words right, 98.2 % before. Notation (`slovenian::Lexicon`): the word spelled as pronounced with the dictionaries' accented letters (mésto, člôvek, otròk), ə for a schwa, w for an l that is [w], `*` stem, `|` form list, `spelling=pronunciation`; `'` and `:` as ASCII marks. Users write it in `accents.json` with `"language": "sl"` (an entry without a language is used for Slovenian too when it reads in the notation; Slovenian has no verb entries). Regenerate the table with `python3 tools/formant/slovenian_words.py extract <Sloleks.3.1 dir> forms.tsv 0` (13 GB of XML, about 4 minutes) and `... generate forms.tsv src/formant/formant_slovenian.inc --manual-min 0 --auto-min 100 --form-min 1` (it reads `HAND_ENTRIES` from `src/formant/formant_slovenian.cpp`, so regenerate after changing them). Clitics: the monosyllabic prepositions and conjunctions, ne, naj, the forms of biti and the future, bi, the short pronouns; the preposition v is [w] before a vowel and [u] before a consonant; a spelled acronym is stressed on its last letter (SP [espé]). A compound numeral (enaindvajset) is read as three words, ena in dvajset, with an accent on the ones and on the tens and no pause (SP ênaindvájset; `split_compound_numeral()`). A spelling with two readings (`HEAD_READINGS`) is the greeting or the imperative at the head of a clause and after in/pa/zdaj/prosim (žívijo, narêdi, urêdi, dêli), the present tense or the other word elsewhere (živíjo, naredí, déli). Meni (`clause_reading()`, SSKJ²/SP) is the menu mení only alone in its clause ("Meni", "Meni, gumb"), the pronoun mêni after a preposition or before se/je/ni (k meni, meni je všeč), the verb méni elsewhere. The participle of biti is bilà biló bilí bilè (SSKJ² standard; the stylistic bíla was a hand entry until 2026-10-30). A spelling that is a verb's form in one reading and a noun's, adjective's or adverb's in another (909 in the generated `SLOVENIAN_VERB_NOUN`: veselí/veséli, letí/léti, vôzil/vozíl) is read by `context_reading()`: a preposition or dve/obe right before it → the noun, ne → the verb, an agreeing auxiliary right before a participle (je vozil, so sporočili; not -lo) → the verb, an -ih adjective before a participle's spelling → the noun; veseli is the verb with se/si in the clause, an object clitic or ne before it or at the clause end, the adjective after a form of biti; leti is the noun only with a preposition, a number or an -imi/-ema word in the three words before it or a form of biti after it. Cues were kept only where they beat the more frequent reading on SUK (93.3 % → 94.8 % of these tokens); clause-final position and an earlier se did worse than nothing in general. A stem of the lexicon followed by -lec/-lka/-lnik/-lnica/-lišče moves its stress before the l (zagánjati → zaganjálnik, brálec, učílnica, gledalíšče). `HAND_ENTRIES` must agree with the Sloleks table unless SSKJ/SP say otherwise (281 of its forms contradicted Sloleks until 2026-10-29, 183 more on 2026-10-30, among them béseda, víšina, séstra, septémber, and the dictionaries sided with Sloleks nearly every time); a hand stem also catches derived words (gôr* read goreti as gôreti), so prefer whole forms, and a deviation for every form of a word goes into `CORRECTIONS`; emoji are named from `emoji_sl.json` (CLDR sl), loaded by the engine next to `emoji.json` and consulted before it while Slovenian is spoken. Letter names (Pravopis § 7): a, be, ce, če, de, e, ef, ge, ha, i, je, ka, el, em, en, o, pe, er, es, eš, te, u, ve, ze, že; ku, dvojni ve, iks, ipsilon; mehki če/dže for ć/đ. Symbols inside a clause: pika, dvopičje, klicaj, odstotkov, evrov, afna; the spelled names of digits and punctuation (ena, pika, vejica, podpičje, vprašaj, oklepaj ...) come from `slovenian::spelled_name()`, used by `spell_character()` before the Croatian `spelling.json`. Tests: `tests/linux/test_frontend.cpp` "[slovenian]", `test_formant.cpp` "Slovenian is spoken by every voice".
- **Synthesis is deterministic**: the same text and settings give the same samples (`tests/linux/test_formant.cpp` relies on it).
- **Acoustic values come from measurements**, not from taste: vowel formants and durations from Bakran's work on standard Croatian, consonant spectra, levels and transitions from analysis of recorded Croatian speech. `docs/formant.md` records the sources, the measured values and how to repeat the measurements. Change numbers in `formant_phonemes.cpp` only with a measurement or a listening test behind them.
- **Stress** is lexical and cannot be fully predicted. To fix a word, add it to `formant_lexicon.cpp` (notation at the top of the file) and check its whole paradigm, not just the dictionary form: the accent often moves in the other cases and persons (sìgnal/signála, podátak/pòdātākā, obavijéstiti/obàvijēstīm), and a stem entry also catches derived words with a different accent (see "Stress" in `docs/formant.md`). Verbs are not listed form by form: `IJE_VERBS` has the roots with a long *ije* (podijeliti, promijeniti), `VERBS` whole stems with accent and conjugation class (`ur'e:d=i`), and `StressRules::verb_form()` builds the forms; an imperative that is also a noun's case (potvrdi, uredi) is the verb only at the head of a clause; users can do the same from a pronunciation dictionary by writing accent marks in the replacement (`telèfon`). Place names and personal names are tables of their own (`formant_proper_names.inc`, edit `tools/formant/places.tsv` or `persons.tsv` and run `tools/formant/proper_names.py`), used only for words written with a capital letter (not in all-capitals text, and after the user's own entries) so that a village or a name never changes the common word it is spelled like; a personal name wins over a place; an entry marked `=` (spelled like a frequent word) is also skipped for the first word of a clause; `proper_names.py` refuses two accents for one spelling. Number compounds of age and time (petogòdišnjī, šestòmjesečnī, malòljetan) are a rule, `StressRules::time_compound()`, and so are Slavic names in -mir/-dar/-zar (Rȁdomīr, Bȍžidār), `StressRules::slavic_compound_name()`.
- **English words** keep the voices' letter sounds but get English stress with a plain (neutral) accent, never the rising one, wherever it falls (Croàtian, Ábleton, Elèven): the table `formant_english.inc` (looked up after the native exact lexicon, before its stems), and for words spelled the English way (`english_spelling()`: q/w/x/y, th, ch, ph, ck, -tion, i before a/e/u, doubled consonants, with native prefix boundaries excluded) the rules in `english_rule()`. A capital after two small letters splits a word into its parts (ElevenLabs → Eleven Labs, ČetDžipiti → Čet Džipiti) unless a lexicon knows the whole word (TikTok) or every part is one syllable (TalkBack); never after one small letter (iPhone, BiH, and the Lj/Nj/Dž of transliterated Cyrillic capitals). `english_word()` strips stress-neutral endings, the -s/-ed/-er/-ing/-ment ones only from English-spelled words because native words end that way too (operater, distributer), and Croatian case endings from any word; native forms that would match (reforma ← reform) are unmarked "stop" entries in the table. Native derivations of English stems keep -irati/-izam (chatirati), and the user's verbs win. To add or correct a word, add a row to `tools/formant/english_extra.tsv` and rerun `tools/formant/english_words.py` (needs `pip install wordfreq spylls`, `cmudict.dict` and the LibreOffice Hunspell hr_HR/sr-Latn/bs_BA files); it keeps native words out (Hunspell) and only writes words the rules get wrong. `english_words.py` mirrors `english_word()` in `lookup()`: change both together. See "English words" in `docs/formant.md`.
- **Users have their own accent lexicon**: `accents.json` next to the user dictionaries, entries in the built-in notation as JSON (`{ "word": "kontr'o:l*" }`, `{ "verb": "ur'e:d=i<p" }`, optional `"language"`). `formant::UserLexicon` parses and validates it once; `Frontend::set_user_lexicon()` consults the user's forms, stems and verbs before the built-in ones. The engine keeps it across voice changes (`TTSEngine::load_accent_lexicon()`, C API `laprdus_load_accent_lexicon()`, report via `laprdus_get_accent_lexicon_report()`); `laprdus_load_user_config()`, both CLIs, SAPI5, NVDA, Android (`LaprdusTTS.loadAccentLexicon`) and Apple (`DictionaryState.accentLexiconURL`) load it with the user dictionaries, and user dictionaries off removes it. Every platform's dictionary editor offers it as the fourth dictionary type (Windows `DictionaryType::Accents` with `AccentEntryDialog` in `dictionary_dialog.cpp`, Android `DictionaryType.ACCENTS`, Apple `DictionaryType.accents`): an entry is word or verb (`verb` flag) plus `language` and `comment`, its text kept in the entry's grapheme field, written under the `word`/`verb` keys; before saving, the editor checks the entry with the engine's own parser (`laprdus_check_accent_lexicon()`, handle-free, returns the number of rejected entries and the first reason; Windows calls `formant::UserLexicon::parse` directly, Android `LaprdusTTS.checkAccentLexicon`, Apple `LaprdusEngine.checkAccentLexicon`) and shows the reason instead of saving. Duplicating an accent entry does not append " (copy)". See "Stress" in `docs/formant.md` and 5.11 in `docs/laprdus.md`.
- **Croatian tiflo- compounds** follow the user's requested two-component pronunciation, including established dictionary terms. `Frontend::process()` splits after `tiflo` when the remaining letters contain a vowel or syllabic r; both parts get their ordinary accent analysis, and the second has `joined = true` so they share one prosodic word without an internal boundary pause. Lowercase, uppercase and inner capitals behave alike. The short falling `t^iflo` is a listener preference; HJP gives single accents in *tiflòlog, tiflològija, tiflòloškī*. Written accent marks and the user's whole-word exact, stem and verb entries override the split. See the source discussion in `docs/formant.md`.
- **Frontend structure tests** (`tests/linux/test_frontend.cpp`) check accents and joined word boundaries directly. Compile them with `src/formant/formant_frontend.cpp`, `formant_lexicon.cpp`, `formant_phonemes.cpp`, `formant_slovenian.cpp` and `src/core/phoneme_mapper.cpp`, using `-I include -I src -I tests/linux`; these internal C++ APIs are not exported by the dylib. Run these alongside the synthesis tests when changing frontend structure. The complete build command is in `docs/formant.md`, section 7.
- Platform code that bypasses `laprdus_set_voice()` must check `VoiceRegistry::is_formant_voice()` and call `TTSEngine::initialize_formant()`, then `TTSEngine::set_language()` when the host chose a language (see the Android JNI bridge and the SAPI5 driver).

**Singing presets.** `orguljas`, `dalmacija_klapa`, `lika_velebit` (Zvonko), `trubac`, `harmonikas`, `solunac` (Stojan), `sevdalija`, `sazlija`, `sarajevo_bembasa` (Mirsad), `becarac` (Zvonko, the bećarac tune) are formant voices whose `FormantVoice::singing` points at a `SingingStyle` (song, sound source, chorus, sub-octave, reverb, vibrato, note envelope, transpose; all in `formant_synthesizer.cpp`). They sing the text to a public-domain folk song, one syllable per note (a `~` note in the song notation is a melisma, `R` a rest), the vowel on the beat with the consonants before it; the song restarts with every synthesis call (`TTSEngine::begin_utterance()`), and clauses of one call continue it. Rate = tempo, pitch = transposition, inflection level = vibrato depth. A preset sings in whichever language is set; its native language is that of its song. `SingingStyle::dry` (lika_velebit, solunac, sarajevo_bembasa) keeps the voice's own source and phonation and transposes the song so the middle of its range sits five semitones above the voice's `base_f0`. Notes without a rest between them are legato: the attack envelope is applied only after a rest or at the start of a clause. Base voice is in `base_voice_id` (platform code uses it only as metadata; `data_filename` stays null). The instrument sources (`SourceKind`), chorus, sub-octave and reverb live in `klatt_synth.cpp`; the speaking voices do not use them and their output is unchanged. See "Singing presets" in `docs/formant.md`.

## Audio Processing

### Recorded Voices (TD-PSOLA)

Rate, pitch and intonation of Josip and Vlado are produced by time-domain pitch-synchronous overlap-add over the pitch marks of the recordings (`src/audio/psola.cpp`), with no third-party library. `docs/concatenative.md` has the full description.

- **Speed** (rate): the planner shortens or lengthens every segment's duration (same rules as the formant voices, rate floors for consonants); the renderer repeats or skips periods. Bursts are never stretched; closures take the time at slow rates and lose it first at fast ones.
- **Pitch** (voice character, derived voices): the spectrum of the recordings is warped by `sqrt(pitch)` at analysis time (a child's vocal tract), and the pitch itself by `pitch` at rendering.
- **User Pitch**: the output period spacing alone; formants stay where they are.
- **Intonation**: the shared `formant::Intonation` model draws the contour from the front end's stress and clause kind.

### Dual Pitch System
Two separate pitch parameters serve different purposes:

| Parameter | Range | Purpose | Effect |
|-----------|-------|---------|--------|
| `pitch` | 0.25 - 4.0 | Voice character (derived voices) | Recorded: formants × sqrt(pitch), F0 × pitch. Formant voices: F0 × pitch |
| `user_pitch` | 0.5 - 2.0 (formant 0.25 - 4.0) | User preference (SAPI5/NVDA slider) | F0 only - keeps voice identity |

`TTSEngine::set_language()` tells the front end of any voice, recorded or formant, which language's rules, lexicon and letter names to use and sets the number dialect (`laprdus_set_language()`, the SAPI5 driver and the Android bridge call it); Josip and Vlado speaking Serbian or Bosnian say *hiljada*.

SAPI5 registers four voice tokens, one per language ("Laprdus Croatian" 0x041A, "Laprdus Serbian" 0x081A, "Laprdus Bosnian" 0x141A, "Laprdus Slovenian" 0x0424), not one per Laprdus voice. The installer removes the per-voice tokens of earlier versions on install, upgrade and repair, and re-registers the four.

### Android storage layout (Direct Boot)

`LaprdusTTSService` is `android:directBootAware="true"` so TalkBack can use Laprdus on the lock screen after a reboot, before the first unlock. Everything the service needs at that point lives in **device-protected (DE) storage** under `/data/user_de/0/<pkg>/files`:

- settings DataStore: `datastore/laprdus_settings.preferences_pb` (opened via `deviceProtectedDataStoreFile`, process singleton in `LaprdusStorage`)
- user dictionaries: `user.json`, `spelling.json`, `emoji.json` (written atomically via `AtomicFiles`), and the accent lexicon `accents.json` (edited as the fourth dictionary type, `DictionaryType.ACCENTS`)

Voice data and bundled dictionaries load from APK assets, so synthesis itself never depends on storage.

**Migration.** Builds 10 and earlier stored this data in credential-encrypted (CE) storage (`/data/user/0/<pkg>/files`), which is unreadable while locked. `SettingsMigrator` and `DictionaryMigrator` copy it once after unlock: DE values win, legacy values only fill missing keys, every step is crash-safe and idempotent (re-running after a crash converges), and the migrators are re-armed on `ACTION_USER_UNLOCKED`, on a rate-limited delayed retry, and on the next process start. Debug builds can force a crash at a named step by writing a `MigrationCrashPoint` name into `files/debug/crash_point` in the DE directory.

**Failure policy.** Storage problems (unreadable or corrupt DE/legacy files, failed copies) never crash: they are logged, defaults are used, a localized notice is shown in the Settings screen (settings) or the Dictionaries screen (dictionaries), and migration is retried later. Only "no voice loadable at all" (requested voice and the default-voice fallback, `zvonko`, both fail) throws `LaprdusEngineUnavailableException`, and only from the synthesis path, so `speak()` returns ERROR and TalkBack can switch engines. A DE crash marker bounds this to 3 throws per 10 minutes; after that the service reports `callback.error()` per utterance instead.

**Backup rules.** `backup_rules.xml` and `data_extraction_rules.xml` must stay empty: with no rules the framework backs up both CE and DE files, while adding any `<include>` flips the file to include-only and silently drops everything not listed.

### Speech Dispatcher Integration

**Automatic Configuration**: When installing LaprdusTTS via packages (deb, rpm, PKGBUILD) or using `scons install`, Speech Dispatcher is configured automatically. No manual configuration is needed.

The installation:
1. Installs the module binary to `/usr/lib/speech-dispatcher-modules/sd_laprdus`
2. Installs the config to `/etc/speech-dispatcher/modules/laprdus.conf`
3. Automatically adds `AddModule "laprdus"` to `/etc/speech-dispatcher/speechd.conf`
4. Sets LaprdusTTS as the default for Croatian (hr), Serbian (sr), Bosnian (bs) and Slovenian (sl)

The module lists every voice for every language; `SET LANGUAGE` calls `laprdus_set_language()` and keeps the voice; `MALE1` is Zvonko for all three languages (MALE2 Josip, MALE3 Đedo, FEMALE1 Baba, CHILD_MALE Detence).

After installation, restart Speech Dispatcher:
```bash
systemctl --user restart speech-dispatcher
```

Test with spd-say:
```bash
spd-say -o laprdus "Dobar dan!"
spd-say -o laprdus -l hr "Hrvatski tekst"
spd-say -o laprdus -l sr "Srpski tekst"
spd-say -o laprdus -l sr -y "Zvonko" "Zvonko govori srpski"
spd-say -o laprdus -l bs -y "Josip" "Josip govori bosanski"
```

**Manual Configuration** (only if automatic configuration fails):
```
# Add to /etc/speech-dispatcher/speechd.conf:
AddModule "laprdus" "sd_laprdus" "laprdus.conf"
DefaultModule laprdus  # Optional: set as default
```

## Spelling

`TTSEngine::synthesize_spelled()` (C API `laprdus_synthesize_spelled()`) reads text character by character, at the normal speech rate, with a pause after every character, including the last. It is what every platform calls for screen reader spelling, typed-character echo, SAPI5 `SPVA_SpellOut` and single-character requests. Per character (`spell_character()`):

- **A letter of the alphabet** (`formant::spelling_letter()`: Latin or Cyrillic, any case, the ligatures and љ/њ/џ as digraphs, ä-type letters folded) is read, by default, by its **sound** (`SpellingMode::LetterSounds`, the default of `VoiceParams`, `UserSettings`, a `settings.json` without the key, the NVDA driver, Android and Apple since 2026-10-18; before that the names were the default and the switch went unnoticed) or, when `VoiceParams::spelling_mode` is `SpellingMode::LetterNames`, by its **name** in the language currently set (`TTSEngine::language()`, for every voice; `formant::letter_name()`: Croatian and Bosnian *a, be, ce, če, će, de, dže, đe, e, ef, ge, ha, i, je, ka, el, elj, em, en, enj, o, pe, er, es, eš, te, u, ve, ze, že*, foreign *ku, duplo ve, iks, ipsilon*; Serbian per decision 41 of the Odbor za standardizaciju srpskog jezika: *lje, nje, ša*, the same for Cyrillic and Latin; Slovenian per Slovenski pravopis § 7: the same names for its 25 letters, *dvojni ve* for w, *mehki če*/*mehki dže* for ć/đ). The sound: `Frontend::letter_sound()` builds an `Utterance` with `isolated_sound = true` (a vowel letter as a stressed syllable; a consonant letter as the consonant plus a stressed SCHWA release vowel, "bə", "sə", "mə", as eSpeak's Croatian voice sounds letters out: measured 70-90 ms of consonant and 110-130 ms of vowel at full level; the foreign letters *q, w, x, y* (`formant::is_foreign_letter()`) keep their names in sound mode too), and `FormantSynthesizer::synthesize_letter_sound()` / `AudioSynthesizer::synthesize_letter_sound()` render it with fixed durations. The same letter names are used for spelled-out abbreviations in running text ("USB", "HR").
- **Everything else** (digits, punctuation, symbols) is read by its entry in the bundled spelling dictionary, or spoken as text when it has none; in Slovenian by the module's own names (`slovenian::spelled_name()`: ena, dve, pika, vejica, afna ...) before the bundled dictionary.
- **The user's spelling entries** (`add_spelling_entry()`, `append_spelling_dictionary()`, a second `SpellingDictionary` layer) win over all of that, with one exception: in sound mode a user entry that is merely a letter's name (`formant::is_letter_name()`: the built-in names of any language, plus the old *jot*) gives way to the sound; any other entry is spoken as written. `load_spelling_dictionary*()` replaces the bundled layer and clears the user layer, so every platform's "load bundled, then add the user's" sequence keeps working.
- **Capital letters announced by a screen reader** arrive as text, not as a spelled character: NVDA "veliko N" (hr/sr/bs) and "cap N", TalkBack "veliko slovo N" (hr), "велико Н" (sr), "veliko N" (sr Latin, bs), VoiceOver "veliko početno slovo N" (hr). `TTSEngine::synthesize()` (and `synthesize_streaming()`) recognize a whole request of *veliko*/*cap*/*capital*, optionally *slovo*/*početno*/*letter*, and one letter, and render the words as text followed by `synthesize_spelled()` of the letter, so the spelling mode, spelling speed and user spelling entries apply on every platform. Anything else ("Plan B", "veliko N je slovo") is ordinary text. NVDA marks a spelled capital by pitch itself: `PitchCommand(offset=capPitchChange)` before the letter and `PitchCommand()` after it, sent only to a synthesizer whose `supportedCommands` include `PitchCommand` (`speech.getSpellingSpeech()` sets the change to 0 otherwise). The add-on lists `PitchCommand`, `RateCommand` and `VolumeCommand`, carries the changes in force with every queued item and applies them in the speech thread just before synthesis (`_applyProsody()`: the slider value, or the middle of the slider when the Laprdus value is forced, plus the command's offset or times its multiplier, clamped to 0-100, then scaled as the slider would be), so NVDA's "Capital pitch change percentage" works for every voice, forced pitch included, and the next item comes back down; NVDA replays a change still in force at the start of every sequence it pushes, so each `speak()` starts from the sliders. `tests/nvda/test_driver.py` runs the driver under stubbed NVDA modules (`tests/nvda/nvda_stubs.py`, after NVDA's `speech/commands.py`) against the add-on's DLL and checks this, the spelling mode read from `settings.json` and its reload, rate and volume commands and the delayed character descriptions: `python tests/nvda/test_driver.py`.
- **Spelling speed** (`VoiceParams::spelling_speed`, 0-100, default 50): characters keep the normal speech rate and acceleration. `spelling_rate_factor()` (2^((s-100)/100): 1.0 at 100, 0.71 at 50, 0.57 at 20, 0.5 at 0) controls cadence only: after each character, append `pause_settings.spelling_pause_ms` plus its rendered duration × (1/factor − 1) of silence. Thus 100 adds no extra silence, 50 adds about 41% of the character duration, 20 about 74% (what 50 added before 2026-10-14, when the base was 3 and the default felt too slow), and 0 adds its whole duration. The last character gets the same pause, so whole-word and individual-character calls have identical spacing; `synthesize_spelled(text, final_pause=false, &final_pause_ms)` / `laprdus_synthesize_spelled_ex()` leave that last pause out and report its length, for a host that times the gap after a spelled character itself. **NVDA's delayed character descriptions** ("Delayed descriptions for characters on cursor movement") speak the character as one utterance and then a second one of `BreakCommand(1000)` plus the description; NVDA pushes the second as soon as the first's index is reported. The add-on plays a `BreakCommand` as silence of its length (it used to become a space) and plays a spelled character without its trailing pause, owing that pause to the next item: another character or ordinary speech gets it (less the real time already spent in silence, so spelling a word keeps its cadence), a break cancels it, so NVDA's one second alone sets the gap before the description, and `cancel()` drops it. C API `laprdus_set_spelling_mode()` / `laprdus_set_spelling_speed()`; `settings.json` section `"spelling": { "speed": 50, "mode": "sounds" | "names" }` (parsed within the section, so its `speed` is not confused with `speech.speed`; only an explicit `"names"` turns the sounds off); keys `spelling_speed` / `spelling_mode` on Android and Apple; CLI `-s` (spell the text), `-S`, `-m`. Every settings screen has the spelling speed in its pauses section and a "spell letters by their sounds" switch, on by default, in its advanced/options section; NVDA takes both from `settings.json`. The voice settings are ordered speed, acceleration, pitch, inflection level, volume everywhere. The inflection on/off switch of version 1.0 is gone everywhere (`VoiceParams`, the C API, `settings.json`, the Android and Apple settings keys): the inflection level at 0 is the monotone, and a 1.0 file's `speech.inflection` is not read, since it controlled a different effect (a pitch jump at the punctuation).
- Tests: `tests/linux/test_formant.cpp` and `test_concat.cpp` (`[spelling]`).

## Spelling Dictionary

The spelling dictionary at `data/dictionary/spelling.json` maps individual characters to their pronunciations for screen reader spelling mode (character-by-character reading). It holds digits, punctuation and symbols only; letters are named by the engine (see "Spelling" above).

### Format

```json
{
    "version": "1.0",
    "description": "Character pronunciation dictionary for spelling mode",
    "entries": [
        { "character": "B", "pronunciation": "Be" },
        { "character": "Č", "pronunciation": "Če" },
        { "character": ".", "pronunciation": "točka" }
    ]
}
```

### Character Categories

The spelling dictionary includes:
- **Numbers**: 0-9 (spoken as Croatian words)
- **Punctuation**: Common symbols with Croatian names
- **Special characters**: @, #, $, etc.

### Usage

- **NVDA**: Automatically used in character mode (reading character-by-character)
- **SAPI5**: Used with SPVA_SpellOut action (spell commands)
- **Android**: Available via `synthesizeSpelled()` API

### C++ API

```cpp
// Load spelling dictionary
engine.load_spelling_dictionary("/path/to/spelling.json");

// Synthesize text in spelling mode
SynthesisResult result = engine.synthesize_spelled("ABC");
// Result audio: "A Be Ce"
```

### C API

```c
laprdus_load_spelling_dictionary(handle, "/path/to/spelling.json");
laprdus_synthesize_spelled(handle, "ABC", &samples, &format);
```

Separate from the Apple app in `Lapplerdus/` (which builds with Xcode), the SCons


| Component | Output |
|-----------|--------|
| Shared library | `build/macos-<arch>-release/liblaprdus.dylib` |
| CLI | `build/macos-<arch>-release/laprdus` |

The CLI is the same source as Linux (`src/platform/linux/cli/laprdus_cli.cpp`)
and plays audio through **CoreAudio** (`HAVE_COREAUDIO`), alongside the existing
PulseAudio and ALSA backends:

```bash
B=build/macos-arm64-release

$B/laprdus -D $B "Dobar dan!"               # speak via CoreAudio
$B/laprdus -D $B -o out.wav "Dobar dan!"    # write a WAV
```

The dylib records `@rpath/liblaprdus.dylib` as its install name and the CLI is
linked with `-rpath @loader_path`, so the binary finds the library sitting next
to it without `DYLD_LIBRARY_PATH`.

Cross-compiling to Intel from Apple Silicon works: `--arch=x64`; `--arch=universal`
(macOS only) builds both slices into one binary.

### macOS release build (distribution outside the Mac App Store)

```bash
./scripts/build-macos-release.sh                 # = ./scripts/build-all.sh macos-release
./scripts/build-macos-release.sh --development   # pipeline check without a Developer ID
```

`scripts/build-macos-release.sh` produces, in `dist/macos/`:

- `Laprdus-<version>-macOS.dmg`: the app with the `LaprdusVoices` extension, archived by
  `xcodebuild archive` (Release, arm64 + x86_64), exported with the `developer-id`
  method, notarized with `notarytool`, stapled, in a signed, notarized and stapled
  drag-to-Applications disk image; plus `Laprdus-<version>-macOS-dSYMs.zip`.
- `laprdus-<version>-macos-universal.tar.xz`: the CLI, `liblaprdus.dylib`, headers,

  built by `scons --platform=macos --arch=universal --codesign-identity=... macos-dist`
  and submitted for notarization as a zip (a tarball cannot be stapled).
- `SHA256SUMS.txt`.

It needs the team's Apple Developer Program membership signed in to Xcode: Xcode then
signs the app with the team's **cloud-managed Developer ID certificate** (the key stays with
Apple, `-allowProvisioningUpdates` uses it; it never appears in `security find-identity`).
`codesign` cannot use that certificate, so without a local "Developer ID Application"
certificate in the login keychain the command-line tools and the DMG stay unsigned and the
tools are not notarized (the script says so). A local certificate is made from a CSR at
developer.apple.com > Certificates > + > Developer ID Application and imported into the
login keychain. Notarization needs credentials stored once with `xcrun notarytool

name). The distributor's own setup notes live outside the repository. `--skip-notarization` signs without

`--skip-cli`, `--output`, `--clean` (Xcode work directory `build/macos-release/`).
The script checks that both binaries of the app are universal, that the hardened
runtime is on (`ENABLE_HARDENED_RUNTIME = YES` in the project's Release configuration,
required by notarization), verifies the signatures and runs `spctl` on the results.
The version comes from `MARKETING_VERSION` in the Xcode project (the SCons version names
the tarball; the script warns when they differ).

SCons options behind it: `--arch=universal`, `--codesign-identity=ID` (env
`LAPRDUS_CODESIGN_IDENTITY`; the library and the CLI are signed after linking with a
secure timestamp and, for the CLI, the hardened runtime; `-` is an ad hoc signature
without either, because library validation would then reject the dylib) and the
`macos-dist` target, which stages `dist/macos-<arch>/laprdus-<version>-macos-<arch>/`
with the Linux tarball's `bin/lib/include/share` layout and packs it. The CLI has two
rpaths, `@loader_path` and `@loader_path/../lib`, so it runs from `build/` and from the
tarball alike.

**Not built on macOS:** SAPI5, the NVDA addon, the Windows config GUI and the
Speech Dispatcher module are all platform-specific and remain Windows/Linux only.

warning rather than failing.

### Structure


- The C++ engine is compiled **directly into both targets** from `src/core`, `src/audio`, `src/c_api` (same approach as the Android CMake build; file references in the Xcode project point at `../../src/...`). C++17, `LAPRDUS_VERSION_*` defines set in build settings.
- Voice data (`data/voices/*.bin`) and dictionaries (`data/dictionary/*.json`) are bundle resources of both targets. **On a fresh checkout, generate voice data first** (`scons ... voice-data` or `./scripts/build-all.sh voice-data`) — `.bin` files are gitignored.
- **What the system needs before it lists the voices** (from Apple's "Creating a custom speech synthesizer" sample and from other working speech extensions; all three were missing until October 2026). Note: on macOS 27 the voice load was still failing after these were added (`TextToSpeech.MultiError`, extension never launched), with the cause not yet found:
  - the extension's `AudioComponents` entry declares `sandboxSafe` (`Config/LaprdusVoices-Info.plist`);
  - the app calls `AVSpeechSynthesisProviderVoice.updateSpeechVoices()` (`SystemVoices.update()` in `LaprdusApp.swift`); registering the extension alone is not enough;
  - the app group is one the platform actually grants: `group.com.hrvojekatic.laprdus` on iOS, `<team id>.com.hrvojekatic.laprdus` on macOS. Both come from the build setting `LAPRDUS_APP_GROUP` (per-SDK in the project file), are expanded into the entitlements, and are read back at run time by `AppGroup.identifier`. A `group.` identifier that the macOS provisioning profile does not list is refused by the system.
- To check what the system did with the voices: `/usr/bin/log show --last 10m --predicate 'process == "axassetsd" AND category == "VoiceDB"'` ("Set N records for loader: ausp_lprd_HKTC" is success).
- Settings use the shared app-group `UserDefaults` suite with the **same keys and defaults as the Android DataStore** (`default_voice` (default zvonko), `speed`, `pitch`, `volume`, `force_speed`/`force_pitch`/`force_volume`, `emoji_enabled`, `inflection_level`, `acceleration`, `*_pause`, `number_mode`, `user_dictionaries_enabled`). The app's Language picker chooses the language of in-app playback only; a system request's language comes from the voice identifier it names. The user pitch slider maps to `laprdus_set_user_pitch`; voice-character pitch comes from the registry via `laprdus_set_voice`.
- User dictionaries are stored in the app group container (`Dictionaries/user.json`, `spelling.json`, `emoji.json`, plus `accents.json` for the formant voices' accent lexicon, edited in the Dictionaries tab as `DictionaryType.accents`) in the **same JSON format as Android**, and are applied both in-app and in the extension. All three files use `grapheme`/`phoneme` entries (that is what every platform's editor writes); the engine's spelling and emoji parsers accept those keys next to the bundled files' `character`/`pronunciation` and `emoji`/`text`.
- One speech request is not one phrase. VoiceOver describes an item as a row of `<voice>` elements (name, value, type), puts `<break>` between some of them, and marks only a part as `<say-as interpret-as="characters">` (a one-character badge count next to a button name). `SSMLParser` therefore returns ordered parts (text, spelled text, pause, phrase boundary), each with its own rate and pitch, and `LaprdusAudioUnit` synthesizes them one by one: a `<break>` is silence of its length, a boundary between `<voice>`/`<p>`/`<s>` elements is the user's comma pause. A spelled part is synthesized without its trailing spelling pause (`laprdus_synthesize_spelled_ex`, reported in `AudioChunk.finalPause`) and owes it to what follows: text with nothing between gets it, a `<break>` or a phrase boundary replaces it (the badge count of "Notifications 1 Tab" is followed by the comma pause alone; before, the spelling pause and the comma pause added up to a gap four times the one before the count), and at the end of the request it is appended, so characters VoiceOver sends one by one keep the spelling cadence. Never decide spelling, rate or pitch for a whole request.
- VoiceOver nests `<prosody>` elements (a neutral outer one, an inner `pitch="+50.0%"` for capital letters); `SSMLParser` treats inner values as relative to the outer ones. The extension logs the markup and the parts of each request (never the text): `log show --info --predicate 'subsystem == "com.hrvojekatic.laprdus"'`.
- Localization: `Localizable.xcstrings` string catalog with en/hr/sr/sl (translations aligned with Android's `values-hr`/`values-sr`/`values-sl`). The built-in demo follows the selected speech language, including Slovenian; once the user edits the text, language changes preserve it. Android does the same with `SpeechSamples`, using the effective speech language (system or forced selection), also for the system's "Listen to an example" text.

### Testing the system voices

After installing/running the app once, the `LaprdusVoices` extension registers with the system. Voices appear under:
- **iOS**: Settings → Accessibility → Spoken Content → Voices
- **macOS**: System Settings → Accessibility → Spoken Content → System voice → Manage Voices

The extension mirrors the Android service behavior: honors host rate/pitch unless the "Force" settings are on, pins volume to 1.0 unless forced, and speaks single grapheme clusters through the spelling dictionary. It always synthesizes with the voice and the language the host's voice identifier names (every voice is listed under hr, sr and bs) — Android's "Force language" setting has no Apple equivalent (Spoken Content always names a concrete voice and language) and is not part of this port.
